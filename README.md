# PM Weekly Report Bot

Slack-бот для трекинга еженедельных 2 часов на разработку/обучение в отделе PM.

## Что делает бот

### Еженедельные часы (2ч/неделя)
- `/task-add` — руководитель создаёт задание (текст, кому, часы) через модальную форму
- `/employee-add @людина Ім'я` — добавить сотрудника в базу бота
- `/employee-list` — посмотреть список сотрудников
- Каждую пятницу (настраивается) бот пишет каждому сотруднику кнопку "Заповнити звіт"
- Форма отчёта: по каждому заданию — Виконано? (так/ні) + години + причина (якщо ні),
  плюс обов'язкове поле "Які ще завдання були виконані цього тижня" + години
- `/team-report [ключ_недели]` — сводка по всей команде: кто ответил, сколько часов, у кого не всё выполнено

### Додатки і прогрес (окремий шар, для таймлайну)
- `/app-add` — створити один додаток вручну: назва, категорія, етапи (поле вже заповнене
  дефолтним списком нижче, можна редагувати), відповідальні
- `/app-import` — масовий імпорт списку додатків з таблиці (Category | Job | Прізвища).
  Прізвища матчаться з уже зареєстрованими через `/employee-add` співробітниками.
  Якщо Job порожній - усі такі рядки об'єднуються в один додаток з назвою категорії.
- `/app-set-stages Назва додатку | Етап1, Етап2, Етап3` — задати/змінити етапи для додатку
  (потрібно після `/app-import`, бо там етапи спочатку порожні)
- `/app-list` — переглянути всі додатки, їх категорії, відповідальних і етапи
- `/app-progress` — співробітник логуує: обирає додаток → бот показує саме його етапи →
  обирає етап зі списку АБО впиши новий (одразу додається до списку додатку) →
  відзначає чекбокс "Наразі на паузі", якщо треба → коментар і години (необов'язково)

Дефолтний список етапів (редагується при створенні кожного додатку):
1. Розробка промпту
2. Розробка бота
3. Тест ПМ (самостійне)
4. Тест всередині тіму ПМ
5. Тест відділом ПМ
6. Ревью ментора
7. Передача Васі
8. Підключення в AV
9. Готово

## Хранение данных

MVP использует простой JSON-файл `data/db.json` (через lowdb). Он создаётся автоматически
при первом запуске. Когда команда вырастет или понадобится более сложная отчётность —
можно заменить `src/db.js` на Postgres/Airtable/Google Sheets без изменения остального кода:
весь проект обращается к данным только через `db.get(...)`.

## Веб-дашборд з таймлайном

Gantt-таймлайн: рядки — додатки (згруповані по категоріях), горизонтальна вісь —
дні, кольорові неперервні смуги — етап, на якому додаток був у певний момент, з
іменами тих, хто це залогував (підпис над стартом смуги).

Якщо додаток позначили "на паузі" - сегмент того ж кольору, але зі штрихуванням,
без додаткового текстового підпису (видно з візерунка).

Якщо в якийсь момент ніхто не логував прогрес - етап "тягнеться" далі з останнього
відомого запису аж до сьогодні, щоб було видно що додаток просто триває, а не зник.

**Важливо: дашборд запускається двома способами, залежно від того, де все крутиться:**

1. **Разом з ботом (для хостингу типу Railway)** — `npm start` запускає і бота, і
   дашборд в одному процесі, щоб вони дивились на один і той самий `data/db.json`.
   Дашборд буде доступний на URL хостингу (Railway сам видає домен + порт).
2. **Окремо, тільки для локальної розробки** — `npm run dashboard` запускає лише
   дашборд без бота, на http://localhost:4000 (порт можна змінити через
   `DASHBOARD_PORT` в `.env`). Зручно, коли бот вже задеплоєний на хостинг, а
   подивитись дані хочеться швидко з ноутбука.

## Установка Slack-приложения

1. Зайти на https://api.slack.com/apps → **Create New App** → From scratch
2. **Socket Mode** → включить, сгенерировать App-Level Token со scope `connections:write` → это `SLACK_APP_TOKEN`
3. **OAuth & Permissions** → добавить Bot Token Scopes:
   - `commands`
   - `chat:write`
   - `im:write`
   - `users:read`
4. **Slash Commands** → создать 4 команды: `/task-add`, `/employee-add`, `/employee-list`, `/team-report`
   (при Socket Mode URL для команд не нужен — просто заполни Command и Short description)
5. **Interactivity & Shortcuts** → включить (для модалок и кнопок)
6. Install App to Workspace → скопировать **Bot User OAuth Token** (`xoxb-...`) → это `SLACK_BOT_TOKEN`
7. **Basic Information** → скопировать **Signing Secret** → это `SLACK_SIGNING_SECRET`

## Запуск локально

```bash
npm install
cp .env.example .env
# заполнить .env токенами из шагов выше
npm start
```

Если всё правильно — в консоли появится: `PM weekly report bot запущено`

## Дальше

1. В Slack написать `/employee-add @Имя1 Имя Фамилия` для каждого сотрудника отдела
   (важно сделать это ДО `/app-import`, иначе фамилии не с чем сматчить)
2. `/app-import` — вставить список додатків из таблицы
3. `/app-set-stages` — для каждого додатку из списка задать этапы
4. Проверить `/task-add` — создать тестовое задание на текущую неделю
5. Чтобы не ждать пятницы при тестировании — временно поменять `WEEKLY_REPORT_CRON`
   в `.env` на время через 1-2 минуты от текущего (формат: минута час * * день_недели)
6. Проверить `/team-report` и `/app-progress` → `npm run dashboard` → посмотреть таймлайн
7. Задеплоить на Railway (см. раздел ниже) — навсегда без терминала
8. Через 2-3 недели использования — решить, нужна ли миграция с lowdb на Postgres/Google Sheets

## Деплой на Railway (без терминала, чтобы не держать компьютер включённым)

1. Зайти на https://github.com → создать новый репозиторий (**New repository**),
   например `pm-weekly-bot` → Private
2. На странице пустого репозитория нажать **uploading an existing file** →
   перетащить туда ВСЕ файлы и папки из архива (кроме `node_modules` и `data/db.json`,
   если они там есть - `.gitignore` в архиве их и так исключает при обычной работе с git,
   но при простой загрузке через браузер надо не тащить их вручную)
3. **Commit changes** — код теперь в GitHub
4. Зайти на https://railway.app → Sign in with GitHub → **New Project** →
   **Deploy from GitHub repo** → выбрать `pm-weekly-bot`
5. Railway сам определит, что это Node.js проект, и запустит `npm install` + `npm start`
6. Открыть созданный сервис → вкладка **Variables** → добавить три переменные:
   `SLACK_BOT_TOKEN`, `SLACK_SIGNING_SECRET`, `SLACK_APP_TOKEN` (значения те же,
   что были в `.env` локально)
7. Вкладка **Volumes** → добавить volume, путь монтирования `/app/data` — это
   сохранит `data/db.json` между перезапусками (без этого Railway будет стирать
   данные при каждом обновлении кода)
8. Вкладка **Settings → Networking** → **Generate Domain** — получите публичный
   URL, по которому будет открываться дашборд (то, что раньше было `localhost:4000`)
9. Проверить логи сервиса (вкладка **Deployments** → открыть последний деплой) —
   должно быть написано `PM weekly report bot запущено`
10. Готово — терминал больше не нужен, бот работает всегда, даже если ваш
    компьютер выключен
